# 함수/코드 주석 규칙

## 원칙: 파일 단위 입출력 주석만
- 함수/라인 단위로 "왜"·"무엇"을 설명하는 주석은 쓰지 않는다. 장황해질수록 오히려 코드를 읽기 힘들게 한다.
- 입력·출력 값이 존재하면, 최대한 간단하게 명칭 위주로 **파일 상단**에 명시한다 (함수 단위 아님, 파일 단위).
- 파일 상단에는 파일의 역할을 2~3줄로 간단히 작성 가능.
- 이 두 가지(입출력 요약 + 역할 설명) 외에는 원칙적으로 주석을 추가하지 않는다.

## 최신성
- 코드 변경 시 파일 상단 주석도 함께 갱신한다.
- 코드와 안 맞는 주석은 없는 것보다 해롭다 — 갱신 불가하면 삭제한다.

## TODO/FIXME 형식
- 형식: `TODO(이름, 날짜): 내용`
- 방치된 TODO는 정기적으로 점검해 정리하거나 이슈 트래커로 옮긴다.

## 금지 대상
- 현재 작업 내용, 이슈 번호, "누가 요청해서" 같은 히스토리성 언급은 주석에 넣지 않는다.
- 그런 맥락은 커밋 메시지에 남긴다 (CLAUDE.md 외과수술식 수정 원칙과 일치).

## 언어
- 한국어를 기본으로 사용한다.
- 필요 시(외부 라이브러리 컨벤션 준수, 영문 코드베이스 등) 영어 사용 가능.

## 적용 주체
- 코드 변경으로 생기거나 어긋나는 주석의 추가·삭제·조정은 Orchestrator가 직접 수행한다.
- 워커(도메인 구현 서브에이전트 등)에게 위임한 코드 변경 결과에 주석이 포함돼 있어도, 반영 전 Orchestrator가
  이 문서 기준으로 다시 검토·조정한 뒤 파일에 적용한다 — 워커의 주석 판단을 그대로 신뢰하지 않는다.
